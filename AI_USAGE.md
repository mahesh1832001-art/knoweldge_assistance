# AI Usage Disclosure

## 1. Purpose

AI tools were used as development assistants while building the Knowledge Assistance application. They helped with implementation planning, understanding technical concepts, debugging errors, improving code structure, and preparing project documentation.

The application integrates document processing, Retrieval-Augmented Generation (RAG), semantic search, relational storage, and Large Language Models (LLMs).

## 2. Areas Where AI Assistance Was Used

### Architecture and Design

AI assistance was used to explore and document the application's architecture, including:

- FastAPI backend and React frontend organization.
- Separation of API routes, services, database operations, and vector storage.
- RAG workflow design.
- MySQL and ChromaDB responsibilities.
- LLM integration and fallback strategies.
- Rate limiting and application logging.
- Potential scaling approaches for larger document collections.

### Backend Development

AI assistance supported the development and understanding of:

- FastAPI endpoints for document upload, document listing, and question answering.
- Request validation and HTTP error handling.
- PDF and TXT file processing.
- Text chunking and embedding generation.
- SQLAlchemy models and database operations.
- ChromaDB vector insertion and similarity search.
- Answer caching and question history.
- Transaction IDs, logging, and rate limiting.

### LLM and RAG Integration

AI assistance helped explain and implement concepts related to:

- Generating embeddings using Sentence Transformers.
- Retrieving relevant document chunks using vector similarity search.
- Passing retrieved context to an LLM.
- Returning answers with source references.
- Integrating OpenAI as the primary LLM provider.
- Configuring Google Gemini as a fallback provider.
- Handling provider failures and repeated requests.

### Frontend Development

AI assistance supported the development of the React interface for:

- Uploading PDF and TXT documents.
- Displaying uploaded documents.
- Submitting questions to the backend.
- Displaying generated answers and source references.
- Handling API communication and frontend errors.

### Debugging and Validation

AI assistance was used to investigate and resolve development issues involving:

- Backend and frontend connectivity.
- CORS configuration.
- Database connectivity.
- Vector retrieval behavior.
- File validation and upload errors.
- API response handling.
- Logging and exception handling.

Suggested fixes and code changes were reviewed and applied during development. The application should continue to be validated against actual runtime behavior.

### Documentation

AI assistance was used to prepare and organize:

- `README.md` for setup, features, and API usage.
- `ARCHITECTURE.md` for system design, RAG flow, database design, and scaling considerations.
- This disclosure document.

## 4. Developer Responsibility

AI-generated suggestions and code are not assumed to be correct simply because they were generated by an AI tool.

The developer is responsible for:

- Understanding the application's architecture and implementation.
- Reviewing generated or suggested code before using it.
- Verifying database operations and API behavior.
- Validating file uploads and error-handling paths.
- Checking the relevance of retrieved document chunks.
- Evaluating whether generated answers are supported by source documents.
- Protecting API keys, credentials, and sensitive data.
- Maintaining and improving the application.

## 5. Known Limitations

The application and its AI-assisted implementation have limitations that require consideration:

- Semantic retrieval may return irrelevant or incomplete chunks.
- LLM-generated answers may be inaccurate or unsupported by retrieved context.
- Answer caching can return stale information if document changes are not reflected in cache invalidation.
- The current in-memory rate limiter does not share state across application instances.
- MySQL and ChromaDB do not share a single transaction, so partial failures during ingestion require recovery handling.
- Fallback LLM availability depends on valid configuration, network connectivity, provider availability, and API limits.

These limitations should be evaluated and addressed before production deployment.

## 6. Privacy and Security

API keys and credentials should be stored in environment variables rather than committed to source control.

Sensitive information, credentials, and private documents should not be submitted to AI tools unless their use is authorized and appropriate for the applicable privacy requirements.

Application logs should avoid exposing secrets or unnecessary sensitive document content.

## 7. Transparency Statement

AI tools assisted with planning, coding, debugging, explanations, and documentation. They were used as development aids rather than as a substitute for reviewing and understanding the implementation.

The developer remains responsible for the final code, testing, security, and behavior of the Knowledge Assistance application.
